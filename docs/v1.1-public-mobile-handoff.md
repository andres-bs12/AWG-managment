## Root cause and shared repair

Source inspection confirms the reported mechanism: html/body/root had a fixed percentage height; PublicLayout created a second vertical scrollport; usePublicActions reduced that scrollport and fixed the bar outside it. Its visualViewport/innerHeight comparison could classify Safari chrome as a keyboard. A fixed bar at the layout viewport bottom and the shortened shell explain the missing actions and hard cut. Exact iOS 26 rendering has not been reproduced here.

PublicLayout now has minimum small/dynamic viewport height and no vertical overflow container. html/body use the sky background, while WinterBackdrop and Snowfield remain fixed. `overflow-x: clip` does not introduce another sticky scrollport. The viewport meta already included `viewport-fit=cover` and was preserved.

StickyActions is CSS `position: sticky; bottom: 0` inside the card, with bottom safe-area padding and normal flow on desktop. The measured dock, shell resizing, keyboard heuristic and usePublicActions hook are removed. Buy and QR focus repair scrolls the window using the actual visual viewport; this does not infer keyboard state. Mobile previews stay in flow. At heights ≤640px actions always flow at the card end, including with radio/checkbox focus.

Home uses a 424px mobile reserve for header, title/subtitle, countdown, gaps and both 56px CTAs. The stall uses the remaining `100svh` height with a 64px width floor. Shorter windows scroll naturally. Phone typography has an upper bound so wider phones cannot grow the scene and copy beyond the same budget.
